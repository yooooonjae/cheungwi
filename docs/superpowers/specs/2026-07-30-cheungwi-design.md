# 층위(層位) — 서울 오피스 유효임대료·거래가격·차환 위험 통합 분석 설계

작성일 2026-07-30 · 시리즈 4번째 작품 (수지 收支 → 순환 循環 → 시차 視差·時差 → 층위 層位)

## 1. 작품 개요

오피스 하나를 세로로 자르면 세 개의 층위가 드러난다.

- **공간의 층위** — 타워는 층의 퇴적물이다. 층마다 임대료가 쌓여 NOI가 되고, 불 꺼진 층(공실)은 수입에서 빠진다.
- **자본의 층위** — 그 가치 위에 부채가 지층처럼 쌓인다. Senior 위에 Mezzanine, 그 위에 Equity. 금리가 오르면 부채의 수면이 차오르고 Equity 층부터 잠긴다.
- **시간의 층위** — 지층은 시간이 쌓인 것이다. 개발 PF는 공사·지연·제도(2027년 자기자본비율 5→20% 단계 인상)라는 시간의 위험을 통과해야 준공에 닿는다.

네 가지 연구 질문에 답한다.

1. 건물별 임대료·공실·인센티브를 반영한 정상화 NOI는 얼마인가?
2. 실제 거래가격은 NOI·권역·연식·규모·입지로 얼마나 설명되는가?
3. 금리와 Exit Cap이 0.5~1.0%p 오르면 자산가치와 Equity IRR이 얼마나 내리는가?
4. 만기 시점에 DSCR·LTV 조건을 만족하며 차환할 수 있는가?

1차 결과물은 웹 대시보드(`cheungwi.pages.dev`)다. 보고서·발표자료는 이후 파생물로 만든다.

## 2. 범위

- **표본**: CBD(광화문·을지로)·GBD(강남·서초)·YBD(여의도) 프라임·A급 오피스 50동 내외. 시드 목록은 공개 정보 기반으로 작성해 건축물대장과 대조 검증한다.
- **모델**: 안정화 자산 인수금융(NOI→가치→대출→Equity IRR→차환)과 개발 PF(공사기간 현금흐름·LTC·LLCR·제도 스트레스) 둘 다.
- **비범위(YAGNI)**: 판교·마곡 권역, 오피스텔·리테일, Excel 파일 산출, 영문판, 실시간 서버. 모두 후속 확장으로 미룬다.

## 3. 아키텍처

수지(~/개발)의 골격을 계승한다. 외부 의존 없는 정적 SPA + 로컬 파이프라인.

```
층위/
├── config.json          # API 키 (gitignore) · config.example.json에 키 이름 문서화
├── .env.example         # 경로 변수만 (키와 분리)
├── Makefile             # collect → analyze → build → test / check
├── src/
│   ├── collect/         # 수집기 5종 + common.py (load_config·api_get·재시도)
│   ├── analysis/        # 유효임대료·NOI·cap·가치·인수금융·차환·PF
│   ├── build/           # manifest(관측월≠수집일 원장) → assemble(site/ → web/)
│   └── pipeline/        # refresh.py — 수집→분석→빌드→검증→배포 오케스트레이터
├── site/                # 소스 (index.template.html + css + js) → 빌드 → web/ (dist)
├── data/                # 원천 JSON + data/raw/ 원본 전량 캐시
├── out/                 # 분석 산출물 (배포 데이터)
└── tests/               # 골든·패리티·파서 fixture·물리 게이트
```

- 저장 형식은 시리즈 관례대로 **JSON 단일**. SQLite를 도입하지 않는다.
- 원본 응답은 `data/raw/{source}/…`에 전량 캐시해 재실행을 자동 증분화한다.
- 키 이름은 기존 관례 재사용: `service_key`(data.go.kr) · `rone_key` · `vworld_key` · `ecos_key` · `dart_key`. 원 키는 기존 리포의 것을 복사하되, 오피스 관련 API는 활용신청을 추가한다(자동승인).

## 4. 데이터 계층 — 다섯 개의 층

|---|---|---|---|---|
| 1 | `buildings.py` | 건축물대장 표제부 `BldRgstService_v2` + VWorld(좌표·용도지역·공시지가) | **신규** — archub.py 구조 복제(빈 바디 대응 `Accept` 헤더 포함), vworld.py 재사용 | `data/buildings.json` — 50동 마스터(주소·지번·권역·연면적·층수·사용승인일·주차) |

| 4 | `reits.py` | DART 전자공시 (오피스 보유 상장리츠) | 순환 dart_corp/dart_fin 재사용 | `data/reits.json` — 리츠 임대수익·자산가액. 추정 NOI의 실측 앵커 |

- 시드 50동 목록(`data/seed_buildings.json`)은 건물명·주소·지번을 담고, 대장 매칭 실패 건은 수기 검증 단계로 넘긴다.

## 5. 분석·언더라이팅 엔진

모든 수치 흐름: 유효임대료 → NOI → Cap Rate → 가치 → 대출 → Equity IRR → 차환.

- `effective_rent.py` — 권역 명목임대료에서 렌트프리 관행(권역별 파라미터, 출처 명시)을 환산 차감해 유효임대료를 만든다. 건물별 보정은 연식·규모·역세권 세 특성의 단순 보정 계수로 하고, 리츠 앵커로 캘리브레이션한다. 추정 불확실성 구간을 meta에 기록한다.
- `noi.py` — 유효임대료 × 임대면적(전용률 가정 명시) × (1−공실률) − 운영경비(관리비 상계 가정 명시) = 정상화 NOI.
- `caprate.py` — R-ONE 소득수익률 기반 벤치마크와 실거래 역산(추정 NOI ÷ 거래가)의 **이중 검증**. 두 값의 괴리를 그대로 공개한다.
- `value.py` — NOI ÷ cap 추정가치를 실거래와 비교하고 오차 분포를 공개한다. 잘 맞는 척하지 않는다.
- `acquisition.py` — LTV·DSCR·Debt Yield **삼중 제약의 최솟값이 대출가능액**. 5년 보유 현금흐름 + Exit Cap 매각으로 Equity IRR. IRR·NPV는 수지 feasibility.py의 검증된 엔진을 확장(terminal 매각·임대차 롤오버 신설).
- `refi.py` — 만기 시점 DSCR·LTV 제약 아래 차환 가능 최대금리와 손익분기 공실률을 역산한다.
- `pf.py` — 실제 인허가 사례를 시드로 한 대표 사업지의 월별 Sources & Uses. LTC·이자비용·LLCR. 스트레스 8종(공사비 +5/10% · 준공 지연 6/12개월 · 금리 +1/2%p · 임대 개시 지연 6개월 · 안정화 공실 상승 · Exit Cap +0.5/1.0%p · 매각가 미달 · 차환 LTV 하락) + 자기자본비율 제도 단계(5→20%)별 수익성 변화.

## 6. 대시보드 — 장(章) 구성

- **서장** — 페이지 히어로는 **오피스 타워의 단면 조형**(층의 퇴적 + 자본의 지층이 한 화면에). 이어서 세 권역의 현재 — 임대료·공실·수익률·금리의 최신 계기판.
- **Ⅰ장 공간의 층위** — 50동. 건물을 고르면 층이 쌓이며 NOI가 만들어지는 과정. 추정가치 vs 실거래 산점(평당가×연식×규모).
- **Ⅱ장 자본의 층위** — 언더라이팅. 서장의 단면 조형이 여기서 계측기가 된다: **타워 단면(공실은 어두운 창) 옆에 같은 높이의 자본 스택**. 금리·공실·Exit Cap 슬라이더를 움직이면 부채의 수면이 차오르고 차환 한계선이 건물 허리에 그어진다.
- **Ⅲ장 시간의 층위** — 개발 PF. 공사기간 현금흐름의 지층 단면, 스트레스 8종, 제도 시간표.
- **실험실** — 자유 파라미터 (시리즈 전통).

차트는 수지의 SVG 차트 엔진과 디자인 토큰을 계승하되, 이 작품의 조형 언어(단면·지층·수면)로 재창조한다. 구현 시 frontend-design 스킬을 사용한다. 실험실의 언더라이팅 계산은 JS로도 구현하며 Python과 패리티 대조한다.

## 7. 파이프라인·운영

- `refresh.py` 계승: 수집→분석→빌드→검증→배포(`npx wrangler pages deploy web --project-name cheungwi`). 소스별 독립 실패, 분석 실패 시 `out/` 원자 복원.
- launchd 일 1회 09:10 (시차 08:40과 시차를 둔다). 쿼터 소진 시 다음 날 이어받기.
- 로컬 서빙은 noindex 헤더 + 봇 차단(serve.py 계승).
- CI(GitHub Actions)는 테스트만 수행하고, 산출물 부재 시 skip이 아니라 **실패**한다(시차 패턴).

## 8. 테스트

- **골든** — 손계산 절대값 대조: NOI, NOI÷cap 가치, DSCR, 대출가능액, IRR, LLCR.
- **패리티** — Python↔JS 무작위 케이스 대조(rel 1e-9).
- **파서 fixture** — 수집기별 원본 응답 고정 케이스.
- **물리 게이트** — 연면적÷층수 범위, 평당가 범위, cap rate 범위를 벗어나는 값은 DB-write 전에 차단(G2B 방어 전통).
- **반응형** — CDP 뷰포트 검사. 390px 클램프 함정 주의.

## 9. 정직성 원칙

- 임대료는 개별 건물 실측이 아니라 **권역 지표 + 특성 보정 추정**임을 UI에 명시한다.
- 모든 추정치는 방법·가정·불확실성을 meta에 기록한다. 예측가치와 실거래의 오차 분포를 공개한다.
- 관측월≠수집일을 분리한 원장(manifest)을 유지한다.

## 10. 리스크와 후퇴선

- R-ONE 하위 상권 축이 기대(도심/강남/여의도 분해)와 다르면 → 서울 시도 레벨 + 리츠 앵커로 후퇴.
- 건축물대장 API는 활용신청 필요(자동승인) — 첫 수집 전에 신청.
- 지번 매칭 실패율이 높으면 → 시드 목록에 지번을 직접 보강하는 수기 검증 단계를 둔다.
